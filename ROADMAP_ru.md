# Дорожная карта

Состояние каждого пункта из `docs/PLAN.md` плюс то, что сделано сверх плана.

Русская версия `ROADMAP.md`. При расхождении верна английская — она правится
первой.

Проверено: 29 июля 2026.

---

## Этап 0 — прозрачная труба

- [x] Форкает настоящий сервер, гоняет stdin/stdout/stderr насквозь
- [x] Пишет каждое сообщение в JSONL с направлением и временем
- [x] stderr проксируется 1:1 и не глотается
- [x] Без буферизации: запись и сброс на каждое сообщение
- [x] Тела держатся в `json.RawMessage`, не размаршаливаются
- [x] `bufio.Reader.ReadBytes`, а не `Scanner` — ловушка обрезания на 64 КиБ
- [x] Корректный teardown: EOF на stdin → ожидание → terminate → kill
- [x] Сбор benign-корпуса начинается здесь

**Готово, когда:** клиент через `mcp-guard --` работает ровно так же, как без
него, а в логе лежит полная сессия. ✅ Проверено на
`@modelcontextprotocol/server-filesystem`.

## Этап 1 — протокол, а не байты

- [x] Полный разбор JSON-RPC: request / response / notification / error
- [x] Оба направления, включая запросы, инициированные сервером
- [x] Пакетные фреймы (ревизия 2025-03-26) принимаются
- [x] Корреляция по **(направление, id)**, с TTL и подметанием
- [x] Модель сессии: версия протокола, стороны, список тулов, история вызовов
- [x] `mcp-guard replay` — человекочитаемая расшифровка, офлайн
- [x] Conformance-тест: одинаковые последовательности сообщений с прокси и без

**Готово, когда:** реплей читается, зомби-процессов нет, прозрачность держится. ✅

## Этап 2 — пиннинг

- [x] `mcp-guard approve` → `mcp-guard.lock`
- [x] Записываются команда, argv и **имена** переменных окружения (не значения)
- [x] По каждому тулу: имя, описание, канонизированная входная схема
- [x] Канонизация JSON (RFC 8785 JCS) — защита от ложных срабатываний
- [x] Сверка при каждом `tools/list` и перед каждым `tools/call`
- [x] Несовпадение → внятная ошибка с указанием `mcp-guard approve --diff`
- [x] `mcp-guard watch` — fsnotify на конфигах клиентов
- [x] `mcp-guard verify` — pre-flight проверка, эталон вне каталога конфига
- [ ] Локфайл реального сервера, закоммиченный в репозиторий — механизм есть,
      но ни один сервер по-настоящему ещё не запиннен

**Готово, когда:** сценарий MCPoison блокируется, `--diff` показывает, что
именно изменилось. ✅

## Этап 3 — политика эффектов и taint

- [x] YAML-политика: `allow` / `confirm` / `deny` по имени тула и паттернам аргументов
- [x] Канонизация путей: `~`, `..`, переменные окружения, симлинки, регистр,
      короткие имена 8.3, префиксы `\\?\`, NTFS-потоки
- [x] Сравнение **после** резолва, никогда до
- [x] Дефолтный чувствительный набор: `~/.ssh`, `~/.aws`, `~/.gnupg`, git-хуки,
      `**/mcp.json`, `**/.cursor/**`, `**/.claude/**`, startup-файлы шелла,
      каталоги автозапуска, `**/.env`
- [x] Отдельный exec-класс для тулов с shell-семантикой
- [x] Taint по **источнику**: результат от fetch, почты, issues пачкает сессию
- [x] Эскалация: `allow` → `confirm` для чувствительных эффектов после загрязнения
- [~] Механизм подтверждения — **спросить не умеет**. Протокольный способ это
      `elicitation/create`, и лог рукопожатия доказывает, что ни один
      подключённый клиент его не объявляет. На `strict` confirm отказывает с
      объяснением. Capabilities теперь записываются, чтобы вернуться к этому
      с данными, а не с предположением.
- [ ] Фильтрация окружения дочернего процесса (`AWS_*`, `GITHUB_TOKEN`,
      `*_API_KEY`) — названа в плане в п. 1.3, поле `Options.Env` есть,
      фильтр не написан

**Готово, когда:** CurXecute блокируется **на записи**, и весь benign-корпус
даёт ноль блокировок. Первая половина ✅ (четыре написания, от начала до конца).
Вторая **не доказана** — см. «Что блокирует всё остальное».

## Что блокирует всё остальное

- [ ] **Измерить уровень ложных срабатываний на реальном трафике.** Все
      оставшиеся решения ждут этого. В корпусе 27 сессий и 2 вызова тулов,
      потому что трафик попадает туда только через обёрнутые MCP-серверы.
      Сейчас обёрнуты все четыре (`filesystem`, `fetch`, `context7`, `blender`),
      так что дело должно сдвинуться.
- [ ] **Включить `-enforce`.** Не раньше, чем появится цифра выше. Включить
      «чтобы посмотреть, что будет» — ровно тот способ, которым инструмент
      сносят.

## Продукт, когда на вопрос выше будет ответ

- [ ] Открыть репозиторий — сейчас он приватный, то есть его физически никто не
      может поставить, и он не работает ни как продукт, ни как портфолио
- [ ] Поставить тег релиза и выложить бинарники (сейчас тегов ноль)
- [ ] Добиться десяти установок людьми, которые о нём заранее не знали
- [ ] Только после этого решать, что именно платное. Локальный бинарник — не
      он, никогда. Платят за видимость по флоту, централизованную политику,
      которую разработчик не может отключить, и доказательства для аудита.
      Учти: аварийный выключатель и правило «флаг главнее файла политики»
      правильны для личного инструмента и перевёрнуты для корпоративного
      контроля. Это развилка в дизайне, а не деталь.

## Известные ограничения — записаны, чтобы не открывать заново

- `tools/list` не блокируется никогда, поэтому отравленное описание всё равно
  доходит до модели. Пиннинг останавливает эффект, а не чтение.
- `confirm` не умеет спрашивать. См. этап 3.
- Только stdio. Сервер, добавленный по HTTP, не под охраной, и молча.
- Unicode-нормализация путей (NFC/NFD) не сделана — задокументировано в
  `internal/fspath`, пропущено сознательно, чтобы не тащить `golang.org/x/text`.
- Stdio-прокси не видит исходящий сетевой трафик самого сервера.
